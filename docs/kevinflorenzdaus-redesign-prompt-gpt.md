You are a senior product designer, UX/UI architect, visual design specialist, and senior frontend engineer. Your task is to completely redesign https://kevinflorenzdaus.com/ into a refined, modern personal developer portfolio.

DESIGN DIRECTION: Editorial Swiss Minimalism combined with a Modern Developer Aesthetic. The website must feel professional, technically credible, confident, refined, and personal. Avoid generic freelancer templates, excessive decoration, and trendy effects that compromise usability.

PHASE 1 — AUDIT AND DISCOVERY
Inspect the existing website, all accessible pages, content, navigation, project descriptions, images, links, and existing functionality. Identify the current technology stack and preserve compatible functionality. Do not invent work experience, clients, testimonials, project results, or technical skills. Reuse valuable existing content and improve its presentation and wording. Identify missing content and use clearly marked placeholders where necessary. Produce a concise audit before implementation.

PHASE 2 — DESIGN SYSTEM
Use a warm editorial palette:
- Paper background: #F5F4F0
- Charcoal: #171717
- Secondary grey: #777777
- Rust accent: #D95B35
- White: #FFFFFF

Typography:
- Space Grotesk for headings
- Inter for body text
- JetBrains Mono for technical labels, metadata and code-related details

Use strong typographic hierarchy, oversized headlines, asymmetrical but disciplined grid layouts, generous whitespace, thin dividers, restrained corner radii, and carefully composed imagery. Use consistent spacing and responsive typography. Maintain WCAG AA color contrast and visible keyboard focus states.

PHASE 3 — WEBSITE STRUCTURE
1. HEADER: Minimal navigation with personal wordmark KFD., links to Work, About, and Contact. Keep navigation accessible and responsive. Add a restrained sticky-header behavior if appropriate.

2. HERO: Create a strong editorial introduction. Suggested headline: 'Building digital solutions that work.' Supporting text: 'I develop websites, custom applications and practical solutions using WordPress, Laravel and modern web technologies.' Include clear Explore My Work and About Me calls to action. Show a compact technical identity line such as PHP Developer / Web Developer. Do not overstate experience.

3. SELECTED WORK: Present actual projects using a refined editorial project grid. Each project should include a large screenshot or image, project title, category, technology stack, concise description, and a link to view details. Build dedicated case-study pages or expandable project details if appropriate. Explain the problem, approach, implementation and outcome wherever supported by existing content. Never fabricate metrics or results.

4. ABOUT: Present a concise personal introduction with a strong typographic layout. Focus on practical development, technical problem-solving, building maintainable websites and applications, and improving digital workflows. Use real existing information.

5. SERVICES: Present relevant capabilities such as WordPress Development, Custom PHP Applications, Laravel Development, Website Maintenance, Technical SEO and Process Automation, but only retain services supported by the existing website or confirmed information. Use clear descriptions focused on business outcomes.

6. TECHNOLOGY STACK: Present technologies in a clean, organized layout. Prioritize PHP, Laravel, WordPress and other verified technologies. Avoid unnecessary skill progress bars and arbitrary percentage ratings.

7. TESTIMONIALS: Preserve authentic existing testimonials. Improve typography and layout without changing their meaning or inventing endorsements.

8. CONTACT: Create a prominent closing section with a confident heading, clear contact details and an accessible contact CTA. Preserve working contact methods.

9. FOOTER: Minimal footer with copyright, relevant navigation and verified social links.

PHASE 4 — MOTION DESIGN
Implement subtle, purposeful animations:
- Hero heading: staggered word reveal on initial entry.
- Section entrances: gentle opacity and upward transitions.
- Navigation: smooth underline transitions on hover.
- Project cards: image scale from 1.00 to approximately 1.03 on hover.
- Buttons: subtle directional movement and clear hover feedback.
- Project details: refined image reveals and transitions.
- Page transitions: short, restrained fade where supported.
- Scroll-based animation should be lightweight and must not interfere with reading.

Use CSS transitions and a suitable animation library only if the existing stack supports it. Respect prefers-reduced-motion. Avoid excessive parallax, continuous floating elements, bouncing animations, unnecessary 3D effects and scroll hijacking.

PHASE 5 — RESPONSIVE UX
Design mobile-first and validate desktop, tablet and mobile layouts. Ensure navigation works on touch devices, typography scales properly, project cards stack naturally, buttons have adequate touch targets, images are optimized, and horizontal overflow is eliminated. Maintain content hierarchy across all screen sizes.

PHASE 6 — UX AND ACCESSIBILITY
Implement semantic HTML, proper heading hierarchy, descriptive link labels, keyboard navigation, accessible menus, visible focus states, form validation and useful error/success messages. Include SEO titles, descriptions, Open Graph metadata, canonical URLs where appropriate, descriptive image alt text and structured data where suitable. Optimize image delivery, font loading, layout stability and Core Web Vitals.

PHASE 7 — IMPLEMENTATION RULES
- First identify the current framework, dependencies and project structure.
- Do not replace the existing technology stack without a compelling technical reason.
- Preserve existing URLs and working functionality wherever possible.
- Do not delete existing content or functionality without justification.
- Avoid unnecessary dependencies.
- Keep components reusable and maintainable.
- Use consistent design tokens and component patterns.
- Do not use generic stock imagery as a substitute for actual project screenshots.
- Do not use fabricated testimonials, credentials, client names or project statistics.
- Ensure all navigation and CTA links work.
- Do not stop at a design proposal or static mockup. Implement the actual redesign.

PHASE 8 — QUALITY ASSURANCE
After implementation:
- Run the available build and lint checks.
- Inspect all pages and responsive breakpoints.
- Test navigation, links, forms and interactive elements.
- Check for layout overflow, broken images, console errors and accessibility issues.
- Check reduced-motion behavior.
- Fix identified issues before considering the work complete.

DESIGN QUALITY BAR
The finished website should look like a carefully art-directed personal portfolio, not a prebuilt freelancer template. It should balance personality with professionalism, editorial typography with technical clarity, and visual sophistication with usability.

PRIMARY DESIGN PRINCIPLE:
Show what I build, explain the problems I solve, and make my technical capabilities immediately understandable.

Begin with the website audit, present your findings and implementation plan, then proceed with the redesign. Do not ask for approval for routine implementation decisions. Ask only when a decision requires information that cannot be reliably determined from the existing website.
